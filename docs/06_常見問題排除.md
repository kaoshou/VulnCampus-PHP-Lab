# 06 常見問題排除

本文件彙整了學員在安裝、啟動本靶場以及使用 OWASP ZAP 掃描時，最常遇到的問題與解決對策。

---

## 1. Docker 啟動與容器連線問題

### Q1. 執行 `docker compose up` 時出現 `Ports are not available` 錯誤？
- **原因**：本機有其他服務佔用了 `8080` (弱點版)、`8081` (修正版)、`8082` (phpMyAdmin) 或 `3306` (MariaDB) 埠口。
- **解決對策**：
  1. **確認佔用進程**：
     - Windows 終端機輸入：`netstat -ano | findstr 8080`。
     - 找到最後方的 PID，開啟工作管理員將該進程關閉。
  2. **常見佔用來源**：本機的 IIS、Apache 服務、XAMPP，或本機原先運作的 MySQL/MariaDB 資料庫。
  3. **暫停本機資料庫**：Windows 服務管理員中將 `MySQL` 或 `MariaDB` 服務改為「手動」並點選「停止」。

### Q2. 網頁開啟時出現「Database connection failed...」？
- **原因**：MariaDB 容器已啟動，但其內部的資料庫初始化腳本 (`init.sql` 與 `seed.sql`) 仍在執行中。
- **解決對策**：這是正常現象。首次啟動 MariaDB 時，系統需要時間建立資料表並填入假資料，約需等待 10-20 秒。請稍等片刻，重新整理網頁即可。

## 2. 瀏覽器代理 (Proxy) 與 ZAP 連線問題

### Q3. 設定 ZAP Proxy 後，網頁顯示「連線被拒絕」或「無法連上網站」？
- **原因**：ZAP 的 Local Proxy Port 與靶場的 Port 衝突，或者 ZAP 根本沒有啟動。
- **解決對策**：
  1. 請將 ZAP 的代理埠口改為 **`8090`** (或其他與 8080、8081 不衝突的埠口)。
  2. 確認 ZAP 已正常啟動。
  3. 使用 ZAP 提供的 **Manual Explore** 點選 **Launch Browser**，使用 ZAP 內建的 Chromium 瀏覽器，這會自動設定並綁定代理，最不易出錯。

### Q4. 在瀏覽器網址輸入 `localhost:8080`，但 ZAP 的 HTTP History 完全沒有流量？
- **原因**：現代瀏覽器 (如 Chrome、Firefox) 預設會**繞過 (Bypass)** 本機地址 `localhost` 與 `127.0.0.1` 的代理伺服器設定，直接進行連線。
- **解決對策**：
  1. 在網址列改輸入：`http://127.0.0.1:8080/`。
  2. 如果仍無流量，可將網址改為：`http://localhost.charlesproxy.com:8080/` 或 `http://127.0.0.1.nip.io:8080/`，這能強迫瀏覽器將本機地址解析為外網域名，從而流經 ZAP Proxy。
  3. 最推薦的方式依然是直接使用 ZAP 內建的 **Launch Browser**，該瀏覽器在啟動時會自動停用本機 Bypass 機制。

## 3. ZAP 認證與登入後掃描問題

### Q5. ZAP 在 Active Scan 時，無法掃描到需要登入的個人資料頁 (profile.php)？
- **原因**：ZAP 的 Session 逾期，或者「已登入 (Logged In) / 未登入 (Logged Out) 識別特徵 (Indicator)」設定錯誤，導致 ZAP 無法判斷自己何時被登出。
- **解決對策**：
  1. 重新登入網站，確認「登出」連結的 HTML 原始碼。
  2. 檢查 ZAP Context 中的 **Authentication** 設定：
     - **Logged In Indicator** 可以設為：`Logout`、`登出` 或 `logout.php`。
     - **Logged Out Indicator** 可以設為：`login.php` 或 `登入`。
     - *注意：這些識別特徵對大小寫敏感，且必須確實出現在對應的回應 HTML 中。*
  3. 進入 Context 的 **Users** 面板，確認已啟用該使用者，且帳密正確。
  4. 執行 Active Scan 時，務必勾選該 Users (如 `student01`) 作為掃描身分。

## 4. 掃描效能與時間問題

### Q6. Active Scan 執行時間非常久，卡在某些頁面？
- **原因**：主動掃描會對每一個參數測試數百種攻擊 Payload。若靶場中有後台 Diagnostic 工具 (如 Ping)，ZAP 會執行大量的命令注入與延時攻擊 (如 `sleep 15`)，導致掃描變得很慢。
- **解決對策**：
  1. 對於 Diagnostic 頁面，可以手動在 Sites 樹狀目錄中按右鍵選 **Exclude from > Active Scan**，將其排除在主動掃描外。
  2. 在 ZAP 的 **Policy (掃描策略)** 設定中，將 SQL Injection 或 Remote Code Execution 的強度 (Strength) 設為 `Medium` 或 `Low`，減少發送的 Payload 數量。
  3. 對於本機練習，可直接將主動掃描鎖定在單一檔案 (例如僅對 `courses.php` 按右鍵執行 Active Scan)，無須每次都對整個 Context 進行完整掃描。

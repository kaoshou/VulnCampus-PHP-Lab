# 01 課程靶場使用說明

歡迎使用 **VulnCampus PHP Lab**（校園活動與課程報名平台教學靶場）。本靶場專為《網站弱點檢測與安全改善：ZAP 應用實務》課程開發，提供學員一個安全、隔離且對稱的環境，用以演練 Web 漏洞檢測與程式碼安全修補。

---

## 1. 專案目的與核心目標

本專案的核心目標是提供「弱點版」與「安全修正版」的 Web 應用程式對照，協助學員：
1. 理解 **OWASP Top 10:2025** 的安全風險與實際代碼成因。
2. 學習如何使用 **OWASP ZAP** 進行被動掃描、主動掃描、目錄爬行（Spider / AJAX Spider）及攔截改包測試。
3. 掌握手動驗證（IDOR、商業邏輯缺陷、參數竄改）等自動化掃描工具較難發現的漏洞。
4. 學習安全的 PHP 程式碼撰寫方式（如 Prepared Statements、安全 Session 控制、個資遮蔽等）。
5. 進行修補前與修補後的安全掃描報告比對，驗證安全修補的防護成效。

---

## 2. ⚠️ 安全與合法使用聲明

1. **僅限本機測試使用**：本系統預設僅綁定本機 `localhost` (127.0.0.1) 埠口。請勿修改設定將本服務暴露於網際網路。
2. **禁止非法部署與外網掃描**：請勿將弱點版部署於公開伺服器。本系統僅能用於授權之教學研究或本機環境。
3. **無真實敏感資料**：系統內的所有姓名、電子郵件、電話與身分證字號等資料均為虛擬假個資，不包含任何真實個資。
4. **教學漏洞專用與環境安全**：本系統為資安教學設計，內含刻意保留之真實安全漏洞（如命令注入、SQL 注入、XSS 等）。演練完畢或不使用時，**請務必執行 `docker compose down` 關閉所有容器**，以確保主機安全。

## 4. Docker 啟動與管理指令

### 方法一：使用一鍵管理腳本 (推薦學員快速操作)
- **Windows (點擊兩下或於 PowerShell 執行)**：
  - `start.bat`：一鍵啟動靶場（請等待 10~15 秒供 MariaDB 初始化完成）。
  - `stop.bat`：一鍵停止服務。
  - `reset.bat`：**一鍵重置資料庫**（當資料庫被改壞或想清除測試上傳檔案時，執行此腳本 10 秒快速還原！）。
- **macOS / Linux (終端機執行)**：
  - `bash start.sh`：一鍵啟動靶場（免授權直接執行，或先 `chmod +x *.sh` 後輸入 `./start.sh`）
  - `bash stop.sh`：一鍵停止服務
  - `bash reset.sh`：一鍵重置資料庫與環境

### 方法二：標準原生 Docker Compose 指令 (跨平台通用 / 避免突發狀況)
請開啟終端機 (Windows PowerShell / macOS Terminal / Linux Bash)，進入專案根目錄，可直接執行以下標準指令：

#### A. 快速啟動靶場 (自動建置並於背景執行)
```bash
docker compose up -d --build
```
*說明：此命令會下載基礎映像、編譯弱點版與修正版的 PHP 環境，並在背景啟動 MariaDB。初次啟動需要 1-3 分鐘下載映像。*

#### B. 停止靶場運行 (保留現有測試資料)
```bash
docker compose down
```

#### C. 徹底重置與重建靶場 (清除所有修改並還原種子資料)
在進行多次暴力破解、刪除或新增資料後，若想回復初始種子資料，請執行：
```bash
docker compose down -v
docker compose up -d --build
```
*說明：`-v` 參數會將掛載的資料庫磁碟卷 (db-data) 徹底刪除，重新啟動時 MariaDB 會重新讀取 `db/init.sql` 與 `db/seed.sql` 進行乾淨的初始化。*

#### D. 查看容器狀態與排錯日誌
```bash
# 查看所有容器是否正常運行 (State 應為 Up)
docker compose ps

# 查看即時容器輸出日誌 (按 Ctrl+C 可退出)
docker compose logs -f
```

## 6. 課堂演練指引：弱點檢測、程式修補與安全驗證

本靶場專為防禦與互動式教學設計。在 `docker-compose.yml` 中配置了以下安全掛載保護：
1. **唯讀掛載 (`:ro`) 與即時熱重載**：本機網頁程式碼目錄（`app-vulnerable/` 與 `app-fixed/`）均以唯讀屬性掛載至容器內。這能有效防止學員在演練上傳 Webshell 時篡改或覆蓋本機實體程式檔；同時，**學生在本機編輯器（如 VS Code）修改並儲存程式碼後，變更會即時同步至容器網頁生效，完全不需要重啟 Docker 容器**！
2. **上傳目錄虛擬化隔離**：使用者頭像等上傳路徑（`uploads/`）被單獨隔離掛載至 Docker 內部虛擬具名 Volumes（`vuln-vulnerable-uploads` 與 `vuln-fixed-uploads`）。學員上傳的 Webshell 或測試檔案僅會存留在 Docker 虛擬磁區中，完全不會污染或寫入本機電腦的實體專案目錄，確保主機乾淨安全。

教師可引導學生進行以下「檢測、修補、驗證」的實作循環：

### 步驟 1：使用 ZAP 掃描弱點版
1. 確保靶場已啟動，並使用 ZAP 的 **Manual Explore > Launch Browser** 存取弱點版網站（`http://localhost:8080`）。
2. 在 ZAP 的 Sites 樹狀目錄中，找到目標網頁（例如 `courses.php`），按右鍵選擇 **Active Scan (主動掃描)**。
3. 在 ZAP 的 **Alerts** 面板中確認掃描出的安全性漏洞（如 SQL Injection）。

### 步驟 2：本機手動修補程式碼 (VS Code 雙欄比對)
1. 使用 VS Code 打開專案，定位到 [app-vulnerable](file:///c:/Work/VulnCampus%20PHP%20Lab/app-vulnerable) 底下對應的 PHP 程式檔。
2. **VS Code 左右雙欄比對密技**：
   - 在 VS Code 側邊欄檔案清單中，對 `app-vulnerable/public/xxx.php` 按右鍵選擇「**選取以進行比對 (Select for Compare)**」。
   - 接著對 `app-fixed/public/xxx.php` 按右鍵選擇「**與已選取的項目進行比對 (Compare with Selected)**」。
   - 編輯器將以左右雙欄高亮顯示「修補前 vs 修補後」的關鍵代碼差異，幫助學員快速理解安全防護邏輯！
3. 進行程式碼安全修補（例如將拼接 SQL 語句改為 PreparedStatement 防禦 SQLi）。
4. 儲存檔案（變更會透過 Docker Volume 即時同步至運行中的容器）。

### 步驟 3：手動測試與 ZAP 重新驗證
1. 在瀏覽器重新整理網頁（F5），嘗試進行手動測試，確認漏洞已無法被觸發。
2. 返回 ZAP，針對剛剛有漏洞的網址重新點擊右鍵執行 **Active Scan**。
3. 確認原本紅色的高/中風險漏洞警訊已消失，即可驗證該安全修補完全奏效。

## 7. 常見問題快速排除

- **Q1: 執行 `docker compose up` 失敗，提示埠口 (Port) 被佔用？**
  *A: 請確認本機是否有其他服務佔用了 `8080`、`8081`、`8082` 或 `3306` 埠口。如有，可先暫停本機的 IIS、Apache 或 MySQL 服務後再重試。*
  
- **Q2: 進入網站後，顯示「Database connection failed...」或連不上資料庫？**
  *A: 這是因為 MariaDB 容器仍在啟動初始化中。通常 MariaDB 首次啟動需等待 10-20 秒。請稍等片刻後，重新整理網頁即可。*

- **Q3: 密碼重設之後忘記新密碼，如何回復預設值？**
  *A: 請使用 `docker compose down -v` 徹底清除磁碟卷，再重新 `docker compose up -d` 即可將密碼重設回預設種子資料。*

## 🎯 實作任務闖關清單

### 🏁 Mission 1：環境啟動與自動化被動掃描
- **目標**：成功啟動靶場，並利用 OWASP ZAP 進行站台結構盤點與安全標頭缺失分析。
- **操作指引**：
  1. 啟動靶場（Windows: `start.bat` / Mac: `bash start.sh` 或 `docker compose up -d --build`）。
  2. 開啟 OWASP ZAP，點選 **Manual Explore > Launch Browser** 存取 `http://localhost:8080`。
  3. 點選 **Attack > Spider** 爬行全站。
  4. 檢視 ZAP 下方的 **Alerts** 面板。
- [ ] **完成檢核項目**：
  - [ ] 成功存取弱點版 (8080) 與修正版 (8081)
  - [ ] 在 ZAP Alerts 中觀察到缺少 `Content-Security-Policy`、`X-Frame-Options` 等安全標頭

---

### 🏁 Mission 2：A05 - SQL Injection 主動掃描與繞過驗證
- **目標**：檢測課程搜尋功能的 SQL 注入漏洞，並手動驗證萬用字元繞過。
- **涉及端點**：`/courses.php`
- **操作指引**：
  1. 在 ZAP Sites 樹狀圖中找到 `courses.php`，點擊右鍵 -> **Attack > Active Scan**。
  2. 觀察 Alerts 是否產生 🔴 High 風險的 **SQL Injection** 警報。
  3. 在瀏覽器搜尋框輸入：`' OR '1'='1` 或 `' UNION SELECT 1,username,password,role,5,6 FROM users -- `。
- [ ] **完成檢核項目**：
  - [ ] ZAP Active Scan 成功觸發 SQL Injection 警報
  - [ ] 手動輸入單引號或萬用字元成功撈出全部課程或管理員帳號

---

### 🏁 Mission 3：A01 - 水平越權漏洞 (IDOR) 竊取他人個資
- **目標**：利用一般學員帳號，非法讀取其他學員的隱私機敏個資。
- **涉及端點**：`/profile.php?id=X`
- **操作指引**：
  1. 以帳號 `student01` / 密碼 `password123` 登入弱點版網站。
  2. 進入個人資料頁面，觀察網址為 `/profile.php?id=2`。
  3. 將網址手動修改為 `/profile.php?id=3` (student02 - 李小美)。
- [ ] **完成檢核項目**：
  - [ ] 成功越權查看 `student02` 的姓名、信箱與個人資料
  - [ ] 思考並記錄：為何 ZAP 自動化掃描無法輕易發現此漏洞？（商業邏輯與授權缺陷）

---

### 🏁 Mission 4：A08 - ZAP 攔截改包與參數竄改提權 (Mass Assignment)
- **目標**：使用 ZAP 攔截 HTTP 請求，修改表單隱藏欄位將一般學生身分竄改為管理員。
- **涉及端點**：`/profile.php` (POST 請求)
- **操作指引**：
  1. 在 ZAP 點選綠色圓形的 **Set Breakpoint (設定中斷點)** 按鈕。
  2. 在瀏覽器點選「修改個人資料」並點擊送出。
  3. ZAP 會攔截該 HTTP POST 請求。在 Body 欄位中找到 `role=student`，手動修改為 `role=admin`。
  4. 點擊 ZAP 頂端的 **Step (步進)** 送出請求。
  5. 登出並重新登入 `student01`。
- [ ] **完成檢核項目**：
  - [ ] 成功提權！`student01` 登入後可看到「🔒 管理員後台」選單並進入 `/admin/index.php`

---

### 🏁 Mission 5：A05 - 系統命令注入 (Command Injection) 獲取伺服器控制權
- **目標**：在網路診斷功能中，拼接終端機指令執行任意系統命令。
- **涉及端點**：`/command_injection.php` 或 `/admin/ping.php`
- **操作指引**：
  1. 進入「💻 系統命令注入演練」頁面。
  2. 在輸入框中輸入正常的測試 IP：`127.0.0.1`，確認 Ping 封包輸出。
  3. 輸入命令拼接 Payload：`127.0.0.1 ; whoami` 或 `127.0.0.1 ; id`。
- [ ] **完成檢核項目**：
  - [ ] 成功在輸出框中看到網頁伺服器帳號（如 `www-data`）
  - [ ] 嘗試輸入 `127.0.0.1 ; cat /etc/passwd` 讀取系統帳號名冊

---

### 🏁 Mission 6：代碼安全修補與防護複測 (Secure Coding)
- **目標**：使用 VS Code 修補弱點版程式碼，並在修正版與 ZAP 複測中驗證防護效果。
- **操作指引**：
  1. 使用 VS Code 打開 `app-vulnerable/public/courses.php`。
  2. 比對 `app-fixed/public/courses.php`（使用 VS Code 右鍵「選取以進行比對」）。
  3. 將字串拼接 SQL 改為 PDO `prepare()` 與 `execute()` 參數化查詢並存檔 (`Ctrl + S` / `Cmd + S`)。
  4. 返回 ZAP 對 `courses.php` 再次點擊右鍵執行 **Active Scan**。
- [ ] **完成檢核項目**：
  - [ ] 存檔後瀏覽器 F5 重新整理，手動輸入 `' OR '1'='1` 已無法繞過
  - [ ] ZAP 重新主動掃描後，SQL Injection 🔴 High 風險警報已完全消除
